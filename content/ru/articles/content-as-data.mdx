Самое дешёвое решение в контентном проекте принимается до первой статьи и стоит
дорого, если принять его неправильно: **где лежит контент относительно кода**.

Соблазн очевиден — положить `.mdx` рядом с роутами, в `app/`. Файловый роутинг
Next тогда сам сделает URL, и не нужно ни загрузчика, ни `generateStaticParams`.
Экономия примерно двести строк.

## Что ломается потом

Как только контент лежит внутри `app/`, структура каталогов становится
структурой URL. Дальше любое из этих требований превращается в перенос файлов:

<Callout tone="warning">
  Перенос файла — это смена URL. Смена URL — это редирект, который нужно не забыть
  поставить, и потерянные внешние ссылки, о которых вы узнаете из падения трафика, а не из
  сборки.
</Callout>

- Разделить материалы по годам в файловой системе, но оставить плоские адреса
- Ввести второй язык, не дублируя дерево роутов
- Отдать каталог `content/` редакторам с отдельными правами в git
- Перевести часть материалов на генерируемый индекс вместо обхода файлов

Ни одно из них не требует менять адреса страниц. Но если контент внутри `app/`,
каждое требует.

## Развязка

В этом репозитории `content/` лежит рядом с `src/`, а не внутри. Между ними —
один модуль с четырьмя функциями:

```ts title="src/content/index.ts"
export async function getAllArticles(opts?: {
  includeDrafts?: boolean
}): Promise<Article[]>
export async function getArticleBySlug(slug: string): Promise<Article | null>
export async function getAllSlugs(): Promise<string[]>
export async function getPage(slug: string): Promise<Page | null>
```

Наружу не просачивается ничего о том, что материалы лежат в файлах: ни путей, ни
`fs`, ни расширений. Страница получает объект `Article` и больше ничего.

Проверить это утверждение можно грубым, но честным способом — поискать импорты
файловой системы вне модуля контента:

```bash
grep -rn "node:fs" src/ --include="*.tsx" --include="*.ts" | grep -v "src/content/"
```

Пусто. Значит замена реализации ни одну страницу не затронет.

## Что это даёт по цене двухсот строк

| Требование                       | С контентом в `app/`          | С развязкой             |
| -------------------------------- | ----------------------------- | ----------------------- |
| Плоские URL при вложенных папках | перенос файлов + редиректы    | сортировка в загрузчике |
| Второй язык                      | дублирование дерева роутов    | `locale` во frontmatter |
| Черновики, не попадающие в прод  | ручное удаление перед сборкой | фильтр по `status`      |
| Переход на внешний источник      | правка каждой страницы        | правка одного модуля    |

Последняя строка — та, ради которой всё это и делается. Загрузчик из файлов,
генерируемый индекс, ISR или внешний API отличаются реализацией четырёх функций,
а не архитектурой сайта.

## Границы приёма

Развязка не бесплатна и не всегда оправдана. Для сайта из трёх страниц, которые
никогда не переедут, двести строк загрузчика — чистый оверхед, и файловый
роутинг по `app/` будет правильным выбором.

Она начинает окупаться там, где контента больше, чем помещается в голове, и где
он живёт дольше, чем текущая структура каталогов. То есть примерно с того момента,
когда кто-то впервые говорит: «а давайте перенесём этот раздел».
