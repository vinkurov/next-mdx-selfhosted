Это референс архитектуры контентного сайта: материалы лежат в git как MDX,
схема frontmatter проверяется на сборке, редакторского интерфейса нет.

Репозиторий одновременно служит скелетом: он собирается, поднимается одной
командой в Docker и содержит ровно те решения, которые имеет смысл принять до
первой статьи, а не после сотой.

## Что здесь можно посмотреть

- `src/content/index.ts` — единственная точка доступа к контенту. Наружу не
  просачивается ничего о том, что материалы лежат в файлах.
- `src/content/schema.ts` — схемы Zod, из которых выводятся типы.
- `scripts/validate-content.ts` — проверка контента, падающая с человеческим
  текстом, а не со стеком трейса.
- `Dockerfile` — три стадии; в рантайм попадает только `.next/standalone`.

## Чего здесь нет

Осознанно: ISR, внешнего хранилища медиа, HLS, поиска, роутинга по локалям,
расписания публикаций, редакторского UI, аналитики и форм. Для каждого пункта в
README написано, когда его имеет смысл добавить.
