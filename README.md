# next-mdx-selfhosted

Референс архитектуры контентного сайта на Next.js: материалы живут в git как MDX, схема проверяется на сборке, CMS и базы данных нет.

## Запуск локально

```bash
npm ci
cp .env.example .env
npm run dev
```

Открывается на `http://localhost:3000`. В режиме разработки видны и черновики — так автор смотрит материал до публикации.

## Запуск в Docker

```bash
cp .env.example .env
docker compose up -d --build
```

Если Compose установлен отдельным бинарником, а не плагином к Docker — команда называется `docker-compose` через дефис.

Поднимаются два сервиса: `web` с собранным сайтом и `caddy` с TLS. По умолчанию `SITE_ADDRESS=localhost`, и Caddy выпускает локальный сертификат — сайт открывается на `https://localhost`. На сервере достаточно поменять `SITE_ADDRESS` на реальное имя: сертификат Let's Encrypt Caddy получит сам, конфиг править не нужно.

### Размер образа

Измерено на `linux/arm64` (Apple Silicon), метрика — та, что показывает `docker images`:

| Что                                  | Размер     |
| ------------------------------------ | ---------- |
| Итоговый образ                       | **345 МБ** |
| из них база `node:22-alpine`         | 229 МБ     |
| слой приложения (`.next/standalone`) | 87 МБ      |
| `node_modules` внутри образа         | 78 МБ      |
| └ `@img` — libvips для `sharp`       | 44 МБ      |
| └ `next`                             | 20 МБ      |
| └ `@shikijs`                         | 11 МБ      |

Что в рантайм-образ **не** попало — проверяется одной командой и даёт ноль совпадений:

```bash
docker run --rm --entrypoint sh <образ> -c \
  "ls node_modules | grep -cE '^(typescript|eslint|tailwindcss|vitest|prettier|tsx|@mdx-js|remark-gfm|rehype-slug|rehype-pretty-code|unified|gray-matter|zod)$'"
```

То есть ни TypeScript, ни ESLint, ни Tailwind, ни сам компилятор MDX с его remark- и rehype-плагинами в рантайме не нужны и там их нет: `output: 'standalone'` трассирует только модули, которые сервер реально достаёт, а стадия `runner` ничего не устанавливает — она копирует готовое.

Две честные оговорки, потому что округлённая цифра без них вводила бы в заблуждение:

- **`@shikijs` (11 МБ) в образе остался**, хотя подсветка кода выполняется только на сборке. Shiki резолвит темы и языки динамически, и трассировка не может доказать, что они не понадобятся. Убрать это — значит компилировать MDX в отдельный артефакт заранее; см. [границы v1](#границы-v1).
- **Больше половины образа — это база.** Ориентир «150–200 МБ» достижим на `linux/amd64`, где alpine-база существенно меньше; на arm64 одна база занимает 229 МБ. Цифра выше — измеренная, а не приведённая к желаемой.

## Как добавить материал

1. Создать `content/ru/articles/мой-слаг.mdx` — имя файла становится URL.
2. Заполнить frontmatter: `title`, `description`, `date`, `status`, при желании `tags`, `cover` и `coverAlt`.
3. Положить медиа в `public/media/articles/мой-слаг/`.
4. Прогнать `npm run content:check && npm run media:check`.
5. Открыть PR. `status: draft` держит материал вне продакшена, пока он не готов.

Внутри MDX доступны ровно три компонента — `Figure`, `Video`, `Callout` — и ничего больше. Список задан явным объектом в [`src/content/components.ts`](src/content/components.ts), и всё, чего в нём нет, в MDX не существует. Смысл не в безопасности: контент лежит в репозитории и проходит ревью в любом случае. Смысл в том, что документ, которому доступны три известных компонента, читается в PR как текст и данные. Как только возможны произвольные импорты, ревью контента превращается в ревью кода.

## Архитектурные решения

| Решение                                                                             | Почему так                                                                                                                                                  |
| ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `content/` лежит **вне** `app/`                                                     | Иначе структура каталогов становится структурой URL, и любая пересборка раскладки файлов — это смена адресов, редиректы и потерянные внешние ссылки         |
| Доступ к контенту — четыре функции в [`src/content/index.ts`](src/content/index.ts) | Наружу не просачивается ни путей, ни `fs`. Переход на генерируемый индекс, ISR или внешний источник — правка одного файла, ни одна страница не затронута    |
| Схемы Zod, типы через `z.infer`                                                     | Две написанные декларации разъезжаются при первой правке одной из них, и разъезжаются молча: компилятор доволен, рантайм отвергает настоящие документы      |
| Валидация на сборке, а не в рантайме                                                | Frontmatter пишется руками, поэтому ошибётся каждый. `content:check` падает с именем файла и человеческим текстом до того, как запустится сборка            |
| Невалидный документ — фатальная ошибка                                              | Тихий пропуск — это механизм, за которым стоит каждое «материал просто не появился на сайте». Такие баги дорогие именно потому, что нигде ничего не сказано |
| Белый список MDX-компонентов                                                        | Ревьюабельность контента, см. выше                                                                                                                          |
| `mediaUrl()` из трёх строк                                                          | Переезд медиа на объектное хранилище становится заменой одной функции вместо поиска-замены по всем материалам                                               |
| Только SSG, `dynamicParams = false`                                                 | Неизвестный slug отдаёт 404, а не рендерится по запросу: иначе статический сайт незаметно становится частично динамическим                                  |
| Типографика статей написана руками                                                  | `@tailwindcss/typography` — около 200 стилей, из которых сайт использует пятнадцать, и каждый дефолт пришлось бы переопределять под дизайн                  |
| Версии зафиксированы точными числами                                                | Для референса предсказуемость важнее свежести: клон через год должен собираться так же                                                                      |
| Три стадии в Dockerfile                                                             | В `deps` копируются только манифесты, поэтому слой с `npm ci` переиспользуется на каждой сборке, где зависимости не менялись                                |
| Валидация ещё и внутри сборки образа                                                | Образ — это то, что уезжает в прод. Не должно быть способа собрать его из контента, который CI бы отверг                                                    |
| Адрес Caddy — из переменной окружения                                               | Один и тот же конфиг работает локально по `localhost` и на сервере по реальному имени. Конфиг, который тестировали, — это конфиг, который работает          |

Подробнее, с разбором каждого решения и его цены: [`docs/architecture.md`](docs/architecture.md) и статья [«Self-hosted Next.js с MDX»](content/ru/articles/selfhosted-nextjs-mdx.mdx) в самом репозитории.

### Отдельно про `mediaUrl()`

```ts
const BASE = process.env.MEDIA_BASE_URL ?? '/media'

export function mediaUrl(path: string): string {
  return `${BASE.replace(/\/+$/, '')}/${path.replace(/^\/+/, '')}`
}
```

Эти три строки не нужны сегодня: медиа лежит в `public/media`, и всё работает. Они есть потому, что git — плохой дом для видео, и переезд на объектное хранилище неизбежен. С этой функцией переезд стоит одну правку и одну переменную окружения. Без неё каждый `<Figure>` в каждой статье держит зашитый путь, и миграция становится поиском-заменой по контенту, чьи ошибки видны только как битые картинки в проде.

Это конкретная форма принципа «заложить, но не делать». `locale` и `status` в схеме — из той же категории: одна строка сейчас против миграции всего контента потом.

## Границы v1

Каждый пункт отсутствует сознательно, и для каждого назван порог, при котором его стоит добавить. Отсутствие с объяснением — это решение; отсутствие без объяснения — недоделка.

| Чего нет                          | Когда добавляется                                                                                                                               |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| ISR и on-demand revalidate        | Когда время сборки перестанет устраивать — порядка нескольких тысяч документов                                                                  |
| Внешнее объектное хранилище медиа | Когда медиа перестанет комфортно жить в репозитории; переезд — замена `mediaUrl()`                                                              |
| HLS и транскодирование видео      | Когда появятся длинные видео или заметный трафик. Интерфейс `<Video>` при этом не изменится                                                     |
| Поиск (Pagefind)                  | Ставится за час поверх собранного вывода, закладывать нечего                                                                                    |
| Роутинг по локалям                | `locale` в схеме и путях уже есть; роутинг — когда появится второй язык                                                                         |
| Расписание публикаций             | `status` уже есть; расписание требует рантайма                                                                                                  |
| Редакторский UI (Decap / Sveltia) | Не планируется. Frontmatter держим плоским, чтобы подключался без миграции                                                                      |
| Аналитика и мониторинг            | Self-hosted Plausible или Umami позже; в v1 хватает логов Caddy                                                                                 |
| Формы, комментарии, подписки      | Требуют рантайма, выносятся отдельным решением                                                                                                  |
| Вынос Shiki из рантайм-образа     | Требует компиляции MDX в отдельный артефакт вместо `evaluate`. Стоит 11 МБ образа — окупится, когда размер образа станет проблемой, а не раньше |

### Что это стоит

Минусы тоже часть выбора, поэтому названы прямо:

- **Публикация требует сборки и деплоя.** Опечатку не поправить из браузера за минуту. Для сайта, который правят десять раз в день, эта архитектура не подходит.
- **Двести строк загрузчика**, которых не было бы при контенте внутри `app/`.
- **Нет редакторского интерфейса.** Автор пишет MDX и делает PR. Для нетехнической редакции это блокер.

## Бэкапы

Состояние проекта — это git плюс `public/media`. Отдельного бэкапа нет, потому что нет базы: любой клон репозитория является полной копией контента, а восстановление сводится к `git clone` и `docker compose up`. Резервировать нужно только то, что не в git: том `caddy-data` с сертификатами — и то лишь чтобы не упереться в лимиты Let's Encrypt при частых переустановках. Том с кэшем изображений Next восстанавливается сам при первом запросе.

## Проверки

```bash
npm run lint          # ESLint 9, flat config
npm run typecheck     # tsc --noEmit, strict + noUncheckedIndexedAccess
npm run content:check # схемы всех документов, все ошибки за один прогон
npm run media:check   # все cover, Figure и Video ссылаются на существующие файлы
npm run test          # vitest, content layer
npm run build         # next build
```

Тот же порядок в CI, и контентные проверки идут **до** сборки: малформленный документ падает за секунды с читаемым сообщением, а не через несколько минут внутри стека бандлера. Проверка ссылок запускается по собранному HTML, а не по MDX, поэтому видит адреса, которые реально попали в вывод.

## Как получены медиафайлы

Схема и обложка отрисованы из SVG-исходников в [`assets/media-src/`](assets/media-src) через `sharp`. Демо-видео собрано скриптом [`assets/media-src/render-demo.mts`](assets/media-src/render-demo.mts) из **настоящего вывода** `npm run content:check` — текст в кадрах скопирован с реального прогона против намеренно испорченного документа. Исходники лежат в репозитории, чтобы медиа можно было перегенерировать, а не только унаследовать.
